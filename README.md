
# Інформаційна система бронювання та видачі бібліотечних видань

**Курсова робота з дисципліни «Кросплатформене програмування»**

- **Варіант:** № 4
- **Тема:** Інформаційна система бронювання та видачі бібліотечних видань
- **Здобувач:** Бурніс Артем Євгенійович
- **Група:** 204-ТН

## 1. Опис проєкту

Програмна система призначена для автоматизації роботи бібліотеки. Вона забезпечує облік бібліотечних видань і читачів, створення та опрацювання бронювань, реєстрацію видачі й повернення видань.

Система реалізована за клієнт-серверною архітектурою. Клієнтська частина має графічний інтерфейс JavaFX, серверна частина обробляє HTTP-запити та взаємодіє з базою даних MySQL.

## 2. Технології та вимоги до середовища

Для роботи з проєктом необхідні:

- JDK 21;
- Apache Maven;
- MySQL Server;
- Apache Tomcat 9.x;
- IntelliJ IDEA або інше середовище розроблення Java.

Використані технології та бібліотеки:

- Java;
- JavaFX;
- Java Servlets;
- JDBC;
- MySQL;
- Jackson (JSON);
- JUnit 5;
- Maven.

## 3. Структура проєкту

```text
librarysystem/
├── client/
│   ├── pom.xml
│   └── src/
│       └── main/
│           └── java/
├── server/
│   ├── pom.xml
│   └── src/
│       ├── main/
│       │   └── java/
│       └── test/
│           └── java/
├── database.sql
├── publications.csv
├── test-invalid-header.csv
├── test-invalid-number.csv
├── .gitignore
└── README.md
```

**client** - JavaFX-клієнт, який забезпечує графічний інтерфейс і надсилає HTTP-запити до сервера.

**server** - серверний Maven-проєкт, що містить Servlet, Service, DAO, моделі даних і тести JUnit 5.

## 4. Налаштування бази даних

1. Встановити та запустити MySQL Server.
2. Відкрити файл `database.sql`.
3. Виконати SQL-скрипт у MySQL.
4. Переконатися, що база даних і необхідні таблиці створені.

Параметри підключення до бази даних налаштовуються для серверної частини через змінні середовища:

| Змінна        | Призначення              |
|---------------|--------------------------|
| `DB_URL`      | JDBC-адреса бази даних   |
| `DB_USER`     | Ім'я користувача MySQL   |
| `DB_PASSWORD` | Пароль користувача MySQL |

Реальні паролі та інші секретні значення не потрібно додавати до GitHub.
## 5. Запуск серверної частини

1. Переконатися, що MySQL Server запущений.
2. У кореневій папці проєкту виконати команду:

```bash
mvn -f server/pom.xml clean package
```

3. Після успішної збірки знайти WAR-файл у папці `server/target/`.
4. Розгорнути WAR-файл у Apache Tomcat 9.x.
5. Запустити сервер Tomcat.

## 6. Запуск клієнтської частини

Після запуску сервера відкрити термінал у кореневій папці проєкту та виконати:

```bash
mvn -f client/pom.xml javafx:run
```

Після запуску відкриється графічний інтерфейс системи управління бібліотекою.

## 7. Основні можливості системи

- Додавання, перегляд, редагування та видалення бібліотечних видань.
- Додавання, перегляд, редагування та видалення читачів.
- Створення та опрацювання бронювань.
- Контроль чотиристанного життєвого циклу бронювання.
- Реєстрація видачі та повернення видань.
- Розрахунок інтегрального показника бронювання.
- Імпорт бібліотечних видань із CSV-файлів.
- Валідація даних та обробка помилок.

## 8. Формат CSV-файлу

Для імпорту бібліотечних видань використовується CSV-файл у кодуванні UTF-8.

Очікуваний заголовок:

```csv
title,author,yearPublished,totalCopies,availableCopies
```

Приклад записів:

```csv
title,author,yearPublished,totalCopies,availableCopies
Програмування на Java,Брюс Еккель,2020,5,5
Алгоритми і структури даних,Томас Кормен,2021,4,4
```

Імпорт виконується у фоновому потоці за допомогою JavaFX `Task`. Інтерфейс відображає прогрес, кількість успішно доданих і пропущених записів, а також повідомлення про помилки.

У репозиторії також розміщені тестові файли:

- `publications.csv` — файл із даними для імпорту;
- `test-invalid-header.csv` — файл із неправильним заголовком;
- `test-invalid-number.csv` — файл із некоректним числовим значенням.

## 9. Запуск автоматизованих тестів

Для перевірки серверної логіки використовується JUnit 5.

Запуск тестів із кореневої папки проєкту:

```bash
mvn -f server/pom.xml clean test
```

Повна збірка серверної частини:

```bash
mvn -f server/pom.xml clean package
```

Тестування охоплює розрахунок факторів інтегрального показника, перевірку граничних і некоректних значень, а також допустимі та недопустимі переходи між статусами бронювання.

## 10. Сценарій перевірки основних функцій

1. Запустити MySQL Server.
2. Створити базу даних за допомогою `database.sql`.
3. Запустити серверну частину в Apache Tomcat 9.x.
4. Запустити JavaFX-клієнт.
5. Перевірити додавання, редагування та видалення видань і читачів.
6. Створити бронювання та перевірити послідовність зміни його статусів.
7. Перевірити створення видачі та повернення видання.
8. Перевірити розрахунок інтегрального показника.
9. Виконати імпорт CSV-файлу та перевірити результат.
10. Запустити автоматизовані тести JUnit 5.
